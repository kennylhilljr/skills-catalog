# Agent instructions for skills-catalog

This repository is **public**. Everything you commit is published.

## Layout

- `docs/DESIGN.md`, `docs/SPEC.md`: the design, and the requirements with acceptance criteria (stable IDs such as `CAT-3`). Cite IDs in commits and PRs.
- `inventory/`: `own-skills.{md,json}` are generated by `tools/inventory.py`; do not edit them by hand. `decisions.json` (keep, merge, drop or defer per cluster) and `provenance-overrides.json` are hand-maintained inputs.
- `tools/`: Python 3.9+, standard library only.
- `skills/<name>/` (from M1): one skill per folder; the folder name equals the frontmatter `name`.
- `.held/<name>/`: held skills (`catalog-consumers: "none"`), checked like any skill and delivered to no consumer (DESIGN 3.2). Never move a skill between `.held/` and `skills/` except through the gate that owns it (for `sdd-*`, SPEC SDD-2 to SDD-5).

## Rules

- Never commit content from a private repository or a local-only folder. For those, only a location label, a skill folder name and a content hash may appear. Check a repository with `gh repo view <owner/name> --json visibility` before quoting it; a folder with no GitHub remote counts as private. The one exception: the `SKILL.md` folder of a skill that `inventory/decisions.json` marks `publish: owner-approved`, after the scrub (SPEC INV-9). Nothing else from that source is published.
- A held mirror (`.held/sdd-*`) keeps its source body verbatim; only the frontmatter and the first changelog row differ. Style rules for prose apply once it leaves `.held/`.
- Never commit secrets, tokens, email addresses, internal hostnames or IPs, or absolute or home paths. Write `~/` or repo-relative paths.
- Third-party skill bodies stay out unless promoted (DESIGN section 9).
- Skills on the owner's local exclusion list (`~/.config/skills-catalog/exclude.txt`, untracked) never appear here in any form: no content, name, hash, decision or count, and never in a commit message or PR body. Do not quote the list. See DESIGN 5.1.
- Top-level frontmatter uses only `name`, `description`, `license`, `compatibility`, `metadata` and `allowed-tools`; catalog fields go under `metadata` as strings (DESIGN 4.1).
- Every description says when to use the skill ("Use when..."), with the main use case first.
- Do not edit `catalog-last-verified` by hand; the freshness bot advances it.
- Prose uses no em dashes or en dashes.

## Checks

Until the M1 CI exists, run these before committing:

```sh
python3 -c "import ast; ast.parse(open('tools/inventory.py').read())"
python3 tools/inventory.py --help
grep -rnE '/Users/[a-z]|/home/[a-z]|@gmail\.com|ghp_[A-Za-z0-9]{20}|github_pat_[A-Za-z0-9_]{20}|sk-ant-[a-z0-9-]{10}|sk-proj-[A-Za-z0-9]{10}|BEGIN [A-Z ]*PRIVATE KEY-----' --exclude-dir=.git . && echo "SCRUB FAILED" || echo "scrub clean"
git diff --check
```

Also run `python3 tools/install-hooks` once per clone. It installs `pre-commit` and `pre-push` hooks that run `tools/local_checks.py` on git objects, never the working tree: pre-commit checks the staged index and pre-push checks every commit being pushed, including its message. the exclusion check reads the local exclusion list and prints only file and line for a match, never the name (CAT-19), and the scrub runs `tools/scrub.py` with the CI rules (CAT-10). To run the same checks by hand, use `python3 tools/local_checks.py`. A hook you wrote yourself is left alone; the installer names it and exits 1.

## Do not

- Run anything that writes outside this repository. `tools/inventory.py` only reads other folders.
- Change other repositories from here. Consumer changes (submodule, links, iwb and orchestrator changes) are made by PRs in those repositories.
